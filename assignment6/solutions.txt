The dangling else ambiguity was resolved by restructuring the block_list and block rules into statement and else, explicitly 
requiring {} blocks.
These changes removed the 33 shift/reduce and 11 reduce/reduce conflicts from the parser.
I also added the non-terminal r to distinguish between ID and NUM in PRINT statements, removing the previous ambiguity.


block_list:
    statement block_list    { $$ = ($2) ? mknode(';', $1, NONE, $2) : $1;  }
    | /* empty */   { $$ = NONE; }
    ;

statement:
    '{' block_list '}'                               { $$ = $2;  }
    | WHILE '(' expr ')' '{' block_list '}'                  { $$ = mknode(WHILE, $3, NONE, $6);    }
    | IF '(' expr ')' '{' block_list '}'  else                { $$ = ($6) ? mknode(IF, $3, $6, $8) : mknode(IF, $3, $6, NONE);    }
    | PRINT '(' r ')' ';'                           { $$ = mknode(PRINT, $3, NONE, NONE);  }
    | READ '(' ID ')' ';'                           { $$ = mknode(READ, mkleaf(ID, $3), NONE, NONE);   }
    | expr ';'                                      { $$ = $1; }
    ;

r:
    ID                                              { $$ = mkleaf(ID, $1);  }
    | NUM                                           { $$ = mkleaf(NUM, $1); }
    ;

else:
    ELSE '{' block_list '}'                           { $$ = $3;  }
    | /*empty*/                                     { $$ = NONE;    }
    ;

To implement the execution part I added in syntaxTree.c the function int execute(TreeNode *p), this calls the functions recursively 
on the children of each node in the syntax tree, evaluating expressions, executing statements, and handling control structures like 
if and while.
