B: I make a new file called calculator.y. Which contains the bison code to handle assignment and expressions. 
To make that possible, I had to add two simple lines in lexer.c:

int lexan()  /*  lexical analyzer  */
{
    int c;
    while(1) {
        c = getchar();
        if (c == ' ' || c == '\t')
            ;  /*  strip out white space  */
        else if (c == '\n')
            lineno = lineno + 1;
        else if (isdigit(c)) {  /*  c is a digit  */
            ungetc(c, stdin);
            scanf("%d", &token_value);

            yylval.val = token_value; /* For Bison */

            return NUM;
        }
        else if (isalpha(c)) {  /*  c is a letter */
            int id_number, chars = 0;
            while (isalnum(c)) {  /* c is alphanumeric  */
                lexeme[chars++] = c; 
                if (chars > MAX_ID_LENGTH)
                    error("identifier too long");
                c = getchar();
            }
            lexeme[chars] = EOS;
            if (c != EOF)
                ungetc(c, stdin);
            id_number = lookup(lexeme);
            if (id_number == -1)
                id_number = insert(lexeme, ID);
            token_value = id_number;

            yylval.val = token_value; /* For Bison */

            return symtable[id_number].token_type;
        }
        else if (c == EOF)
            return DONE;
        else {
            token_value = NONE;
            return c;
        }
    }
}

The two simple lines of code: yylval.val = token_value; assigns the semantic value to bison.
This is necessary because when the lexer returns a token (ID or NUM), the parser must also recive the associated value.

With bison is it much easier handle both expressions and assignments, because all the rules are in a single file (.y), and
program automatically generate the code to make it possible.

C:
To add the new operators to calculator, I had to modify calculator.y and extend the grammar. I changed the current "expr" rule to:

    expr:
        arithmetics nonarithmetics conditional
        ;

Here, arithmetics includes all arithmetics operations (+/-/*, etc) while nonarithmetics contains all the new operations except '%', since is equivalent of MOD. 
Finaly, conditional has the lowest priority, so I create a separate non terminal for it. 
These are the new non terminal rules:

        conditional:
            '?' expr ':' expr {emit('?', NONE); }
            | /*empty*/
            ;

        arithmetics:
            term moreterms
            | /*empty*/
            ;

        nonarithmetics:
            '<' expr { emit('<', token_value); } 
            | '>' expr { emit('>', token_value); } 
            | '&' expr { emit('&', token_value); } 
            | '|' expr { emit('|', token_value); } 
            | /*empty*/
            ;
With their corresponding tokens:
    %token <val> NUM
    %token <val> ID LEFT_ID
    %token DIV MOD DONE
    %left '<' '>' '&' '|'
    %left '+' '-'
    %left '*' '/' DIV MOD '%'
    %right '^'      /*right associativity*/
    %right '?' ':'
